# M10：原作者 2026-07-22 版原内核的变化与跟进方案（2026-11-16）

## 1. 版本与方法

- 原作者仓库 IMP-AVAS/AVAS 的 `dllfile/` 保存了各版 AVAS.dll／libAVAS.so。
  - 根目录的 AVAS.dll 链接时间是 **2026-07-22**，比所有带日期的文件夹都新，是最新版。
  - 根目录的 libAVAS.so 含同样的新字符串，视为同一版本的 Linux 构建。
  - M9-notes 第 6 节把 2026-05-27 当作最新，有误。
- 本项目的逐位基准仍是 **2026-04-02 版 AVAS.dll**。
- 方法：
  1. 用 07-22 版 DLL 在 XPS 上跑全部 197 个对齐算例，与基准比较；
  2. 用 04-17、04-22、04-28、05-26、05-27、07-22 六个版本跑 13 个代表算例，确定每个变化出现的版本；
  3. 用 Ghidra 反编译根目录 libAVAS.so，按函数名与已逆向的 .so 逐个对比，分区阅读所有有实质变化的函数。
     伪代码和对比笔记不进仓库，只记结论。
- 注意：已逆向的 .so 与 04-02 版 DLL 本来就有几处不同（50-distribution-rng 第 6 节）。07-22 版有些“新行为”只是 DLL 向 .so 看齐。

## 2. 结果概览

- 197 个算例中 49 个与基准逐字节相同，148 个不同（含 5 个原本就标为未定义行为的）。
- **没有改变的部分**：
  - 粒子推进：Boris、全部硬边矩阵、zTotcode；
  - 场图插值与 Ke／Kb、射频相位；
  - V3 = 0 的同步相位求解；
  - 误差抽样与误差场的算术；
  - 空间电荷求解器（PICNIC、SPICNIC、FFT）；
  - RFQ::GetField（仍不可运行，见 M9-notes）。
  - 用生成分布、经过腔体的算例，同步粒子结果与基准相同。
- **出现时间**：
  - 04-17 起：单粒子输出格式改变，新增 ConvertPlane.txt／ResetPosition.txt；
  - 04-22～05-27：superpose 与报错路径改变，其中 05-26 版的 SP2 又变回报错；
  - **其余物理与约定的变化全部只在 07-22 版**。

## 3. 变化清单

“默认模式”指新内核的默认（修正）模式。“现状”说明新内核目前怎样做。

### 3.1 束流与粒子文件

| # | 变化 | 07-22 版 | 现状 | 判断 |
|---|---|---|---|---|
| P1 | 粒子能量 W 的含义 | W = 总动能，含横向动量（x′ = px/pz）。生成分布写出的 W 因此升高 1e-7～1e-4 MeV；读粒子文件时 vz = βc/√(1+x′²+y′²) | 默认模式在 M3 已改成同样约定；兼容模式按 04-02 版不含横向 | DLL 向 .so 看齐，**已一致** |
| P2 | 读粒子文件时的参考（同步）能量 | 取 beam.txt `kneticenergy`，打印 “Syn particle energy”；只有 kneticenergy < 0 时才用按权重平均的 γβz | 取文件中粒子的平均 W | 约定改变，**待定 D1** |
| P3 | 单粒子初始偏移 | 关键字改名 `displacepos` → `initpos`、`displacedpos` → `initmom`，去掉 ×0.01（x′ 单位 mrad，δ 单位 1e-3）；**旧名字被当作未知关键字忽略**，粒子留在轴上 | 读旧名字，旧单位 | 新功能兼破坏兼容，**待定 D2** |
| P4 | 单粒子能量 | 用实际质量（原为 938.271875） | 默认模式已修正 | 已一致 |
| P5 | 二次粒子文本输入的 γ | 只用 vz 计算 | 用完整速度 | 回归，不跟 |
| P6 | GenBunch（新导出函数） | 独立的生成程序，自带解析与默认值（mc² 938.271875、N 10000、162.5 MHz、2.1 MeV），沿用旧的不含横向的约定，与正常运行的 inData.dst 不一致 | 无 | 不跟 |
| P7 | DC 束 | 能量按 `kneticenergy W ΔW` 展宽；Calculate_Weight 按 βγλ 周期折叠 z | 默认模式已支持 ΔW | 已一致；折叠见 S2 |

| # | 变化 | 07-22 版 | 现状 | 判断 |
|---|---|---|---|---|
| S1 | 平均 γ | `beam.gamma` = 按权重平均的 √(1 + γβz²)，只计纵向动量；影响 DataSet 第 0 列、归一化发射度、rms z 和空间电荷 | 用平均动量 | 定义改变，示例束流下小于 6 位有效数字。UpdateBeamParameters 求和不加权却除以总权重，前后不一致。不跟 |
| S2 | `lpboundary V1 [V2]` | 新的第二个值：V2 = 1 强制 FFT 并使用纵向周期盒；但纵向周期改成 βλ（原 βγλ） | 只有 V1 | 周期边界是新功能，**待定 D7**。空间电荷求解在束流静止系中，周期应为 γβλ；βλ 使网格短 γ 倍（1.5 MeV 质子差 1.6e-3，100 MeV 约 10 %），两条电荷分配路径也不一致，是回归，不跟 |

| S5 | HESCFieldPre 的纵向因子 | 1/√(1 − (c5/γ)²) 改为 √(1 + c5²)，横向质心动量为零时相同 | 照旧 | 可忽略，不跟 |

### 3.5 算例差别的来源

- **读粒子文件的算例**（Z、ER、D_dst 等）：P1 与 P2，经过腔时同步相位随之变化。
- **生成分布的算例**（D_* 系列）：P1。
- **单粒子算例**：
  - P3：粒子留在轴上；
  - O1：输出改变。
  - LB1、LB3（边界碰撞）、EP_D36（t-code 起不来的检查）都是因为偏移被忽略，粒子不再撞壁或离轴，检查本身没变。
- **EP_D18**：O3。
- **S5c**：L1 的越界读取。
- **SP2**（腔在 superpose 块首）：04-02 版报 “Scan phase error”，04-22、04-28、05-27、07-22 版运行、05-26 版又报错。07-22 版的 synData 中 φs、φRF 仍为 NaN、出口能量等于入口（1.52703 MeV），即腔的场仍然丢失（2.6.5.2 缺陷 1 未修），只是扫相位失败后不再报错；各版本在报错与继续之间来回，和这一路径读取越界的未定义行为一致。新内核默认模式不受影响（第 6.5 节）。

## 4. 对两个问题的回答

- **新内核要不要跟到 07-22 版？**
  - 物理核心没有变；P1 默认模式已经一致。
  - 值得跟的是几项新功能：命名输出面、多个输出面同时记录、新边界形状、射频场 Ke = 0 当漂移、纵向周期边界。
  - 约定的改变（P2、P3、O1）要由你决定。
  - 07-22 版自身的回归不跟：S5c 崩溃、二次粒子 γ、lpBoundary 的 βλ、椭圆边界判据、误差场块外取场、单粒子表头被清空。
- **随软件附带的原内核要不要换成 07-22 版？** 建议**暂不换**：
  1. 界面束流页写的是 `displacepos`／`displacedpos`，07-22 版会静默忽略，单粒子偏移失效且没有任何提示；
  2. 单粒子不再写 DataSet，界面的包络图、结果页会是空的；
  3. 有新的崩溃（参数不足的 field 行）；
  4. 已有运行记录换内核后无法复现；
  5. 兼容模式与对齐算例都以 04-02 版为基准，换基准要重新逆向 07-22 版的 DLL（静态 CRT，libm 舍入也会变）。

## 5. 待定点（推荐项列在前）

1. **D1 读粒子文件时的参考能量**：
   - **推荐**：跟随 07-22 版，以 beam.txt `kneticenergy` 为参考能量；beam.txt 写负值时用粒子平均。与粒子平均相差超过 1 % 时打印警告，界面运行前的检查同样提示。兼容模式保持平均 W。
   - 或者：保持平均 W，只在两者不同时警告。
2. **D2 单粒子初始偏移的关键字**：
   - **推荐**：新内核同时接受两套。`initpos`（mm）、`initmom`（x′、y′ 为 mrad，δ 为 1e-3）用新单位；旧名字保持旧单位。同时写了两套时以新名字为准并警告。界面暂时继续写旧名字，等附带的原内核换代时再改；schema 加入新关键字。
   - 或者：只跟新名字。旧项目的单粒子偏移会失效，不推荐。
3. **D3 单粒子输出**：
   - **推荐**：默认模式新增 SingleParticlePlane.txt（格式同 07-22 版）；DataSet 行、outData_*.dst、SingleParticle.txt 的表头照旧保留，界面靠它们画图。
   - 或者：完全照 07-22 版去掉 DataSet 行和 outData。
4. **D4 输出面**：**推荐**默认模式支持 `outputplane z NAME` 命名，并允许面间距小于束长（多个输出面同时记录）。`nplanes` 接受但不需要（新内核按需分配）。兼容模式仍报错。
5. **D5 边界**：
   - **推荐**：默认模式支持形状 3、4 与复合形状 0（局部坐标、椭圆用 y 动量），采用 z 偏移的修正和 L4 子场孔径规则。
   - collisionData.txt 加第 11 列（superposeout 块数），先查界面读取是否受影响。
   - “一步越过整段短管”的检查按正确的局部坐标实现。
6. **D6 射频 field 行 Ke ≈ 0 当作漂移**：**推荐**默认模式支持，参数不足照常报错。界面的“关闭腔体”可以直接用它，以后另议。
7. **D7 纵向周期边界 `lpboundary V1 1`**：**推荐**默认模式支持，周期用 γβλ（静止系），不照抄 βλ；连续束（DC）和长束团可用。
8. **D8 附带的原内核与兼容基准**：**推荐**都保持 04-02 版（第 4 节）。另在 docs/engine 记下 07-22 版的差别，供用户自己换用原内核时参考。

工作量估计：
- D1、D2、D3、D6 都是小改动；
- D4（多面同时记录、命名）和 D5（新几何、局部坐标）各需要新增对齐算例和单元测试；
- D7 要改空间电荷网格的纵向边界，并做物理检验。
所有改动只在默认模式中进行，兼容模式与对齐结果不变。

## 6. 实现（2026-11-16，D1–D7；D8 不改代码）

用户同意第 5 节的全部推荐项。所有改动只在默认模式中生效；兼容模式在 Mac 上对全部 197 个对齐算例的输出与改动前逐字节相同（只差时间戳），`run_all.py` 的兼容模式最大相对差仍为 3.4e-11。

### 6.1 各项的做法与实施中的决定

- **D1 参考能量**（beam.cpp `init_from_dst`、synchronous.cpp `setup`）：
  - beam.txt `kneticenergy` > 0 时取它；≤ 0 或不写（默认 −1）时取文件按权重的平均 W（不跟 07-22 版的“平均纵向动量”）。推荐项写“负值用平均”，W = 0 没有物理意义，一并按“不写”处理。
  - 相差超过 1 % 时内核打印警告；单粒子模式的 .dst 分支同样处理。`.edst` 文件自带同步记录，07-22 版也不变，保持取同步记录。
  - 界面：`run.check` 返回 `warnings`（`kernels.input_warnings`，只对新内核默认模式），运行前以提示条显示并写入日志；`engine.check` 的返回不变。
  - 线性模型 `avas/model/beam.py` 用同一规则取参考能量，rms 矩仍关于平均值，并给出同样的警告（`dst_energies`、`reference_energy_note`）。
- **D2 initpos／initmom**（params.cpp、beam.cpp `init_single`）：新单位（mm；mrad 与 1e-3）；同时写了旧名字时用新的并分别警告；兼容模式仍是未知关键字。schema 的 initmom 第三个参数改为 δ（1e-3），并写明两版原内核各认哪套名字。束流页仍写旧名字。
- **D3 SingleParticlePlane.txt**（tracker.cpp `dst_out`）：每次写输出面时追加一行 `z W x γβx y γβy t`（fixed 12 位），z 段内的输出面（元件中点）与末端都写；粒子没有记录（已丢失）时不写。运行开始时截断；DataSet 行、outData、SingleParticle.txt 及其表头不变。
- **D4 输出面**：
  - 命名：`outputplane d NAME`（检查文件名字符），名称跟随输出面进入 t 段事件和 z 段元件；z 段里的命名面保留名称（07-22 版丢失）。同一 z 的几个输出面合成一个事件、每个名称写一份；一个命名面放在末端时既写 `NAME_<L>.dst` 也写 `outData_<L>.dst`。
  - 同时记录：不改内核，在 tracker 的主机端加 `planeStore_`（见 40 §4.2.6 的说明）。条件 zMax + 2c·dt ≥ 下一事件时才复制，正常间距的运行不经过这条路径，所以已有算例逐字节不变；所有设备用同一套 download／upload，结果一致。
  - 限制：两个面的间距小于一步行程时，后一个面在下一步按直线外推记录（07-22 版相同），漂移段中与单独放这个面的结果只差舍入（M10_D4_close_planes 的 P3：2.5e-16）。
  - `nplanes` 接受并忽略（打印说明）。
  - “steerer 之后的输出面不再丢弃”：默认模式（和兼容模式）自 M2 起就按 DLL 的做法不丢弃（M2-notes 第 8 条：DLL 不检查 `p > ev.back()`；丢弃的是 .so），无需改动。
- **D5 边界**（lattice.cpp `read_boundary`、kernels.h `geom_hit_one`／`geometry_hit`／`boundary_particle`、f32_kernels.h 预筛选、secondary.h）：
  - 形状 3、4。superpose 块只有一个子形状时同以前；多个子形状合成复合段（形状 0，长度与 lattice superpose 相同），子形状按顺序检查、第一个碰撞即返回。superposeend 被吃掉（以前会被当作未知形状）。
  - “一步越过整段”在段搜索向下游走过的每一段和复合段的每个子形状上检查，用局部坐标与 y 坐标。
  - 圆管粒子从入口面进入时在面上已在孔径外的，碰撞点取入口面，插值系数限制在本步之内（以前可能外推到本步之外）；矩形、椭圆管用二分求壁上的点。这两点不改变已有算例（LB1–LB4 的碰撞记录除新增的一列外相同）。
  - z − 行偏移；L4（有 boundary.txt 时不判叠加子场孔径）；collisionData.txt 末尾加 superposeout 块数（avas/ 中没有程序按列读取 collisionData.txt）。
  - GPU：CUDA fp64 直接用共享的 kernels.h；Metal 和 emu fp32 的浮点预筛选对复合段、换段的粒子一律交给主机双精度判断，新形状加了保守的阈值。
  - 模拟设置页（以及文件页）的边界表格列标题与提示改为可翻译，说明四种形状与 a、b 列的含义。
- **D6 Ke = 0**（lattice.cpp `rf_off`）：需要完整的 10 个词；不足时照常报错，不越界。线性模型（`Statement.rf_off()`）同样当漂移段（不读场图、不建腔），分段运行重定相位时跳过它（synData 中是 drift 行）。
- **D7 纵向周期盒**（params.cpp、spacecharge.cpp、mesh_kernels.h、f32_host.cpp `MeshF`）：见 60 §2.4.2 的说明。在 GPU 上同样支持（Metal、CUDA 共用 `mesh_cell_t`／`mesh_corner`／`mesh_trilinear` 的周期折回），没有设 CPU 限制。

### 6.5 其余行为差异的核对（2026-11-16）

第 3 节标为“实施时核对”或“原因未细查”的三项，核对后都不需要改内核：

- **L6 superpose 漂移子块**：默认模式自 M2 起按正确步长 `20 + 20j` 识别 drift 子块并登记位置（只作孔径），与 07-22 版的修正相同；有 boundary.txt 时按 D5 的 L4 规则不判子场孔径。兼容模式保留 AVAS.dll 的 `15 + 15j`。
- **S3 误差研究中的同步粒子**：新内核两种模式的同步粒子都只用无误差的场（kernels.h `external_field_t` 中 `i == b.sync` 时不进 `element_err_field_t`）。兼容模式在含 t-code 误差的算例（如 ER18 腔静态加动态误差）上与 04-02 版 AVAS.dll 逐字节相同，说明 04-02 版本来就如此，07-22 版的 `|| i == N` 只是把它写明。
- **SP2 腔在 superpose 块首**：默认模式写出正确的 20 词 RF 片头（M2），SP2、SP3 的四个算例 φs 都解出 −33°，出口 γβz 相同（0.0631083，相对差 5e-14）、能量 1.527 → 1.867 MeV；`run_all.py` 新增 `superpose_rf_check` 检查这一点。腔在块尾、块中间（V3 = 0）时两种模式都正常（spec 10 实测更正一节已澄清：与同长 drift 叠加属于块首）。07-22 版仍丢场，若用户自行换用该版原内核，含块首腔的 lattice 不加速且没有报错。

### 6.6 第 3 节“不跟”各项的复查（2026-11-16）

逐项复查后只有 S4 的停滞判丢条件需要改，而且是新内核两种模式共有的错误；其余维持原判断：

- **S4 停滞判丢**：tcode 每步统计已越过下一平面、尚未输出的粒子数，连续不变的步数超过全局步数的 80 % 时，把还没越过的粒子判丢。复查时发现 AVAS.dll 2026-04-02 本来就要求 `step > 2000`（反编译 `FUN_180070b90`），旧 libAVAS.so 没有，07-22 版 .so 补上；新内核的规格（40 §4.2.17）按旧 .so 写，两种模式都漏了这个条件，已有算例没有一个在前 2000 步触发，所以一直没被发现。新算例 `M10_S4_stall_early_dst`（3 个粒子，头部领先 60 mm，起点后 10 mm 有输出面）：AVAS.dll 三个粒子都到达两个输出面；改正前新内核在第一个输出面之前把后面两个粒子判丢（兼容模式随即因只剩一个粒子而报“全部丢失”）。另一个 19 + 1 个粒子的算例排除了“DLL 把同步粒子计入越过数”的解释（DLL 同样不判丢）。改正后两种模式都要求 `step > 2000`，兼容模式与 AVAS.dll 在 Windows 上逐字节相同，默认模式由 `run_all.py` 的 `stall_check` 检查；改动前后全部 203 个算例的默认模式输出相同。Windows（XPS，MSVC + CUDA 12.4）上 `run_all.py --strict` 全部逐字节相同，GTX 1650 fp64 173/173、fp32 204/204。“全部丢失前写 FullParticle.txt”两种模式早已如此（tracker.cpp 两处 `full_particle_out()`）。
- **S5 HESCFieldPre 的纵向因子**不跟：质心有横向动量时，变到质心纵向速度为零的参考系，所需的 z 向变换是 1/√(1 − βz²)，即 04-02 版的写法；07-22 版的 √(1 + c5²) 不是这个变换。
- **SingleParticle.txt 被清空**：新内核两种模式本来就在初始化时以覆盖方式写出 3 行表头（beam.cpp `init_single`），重复运行不会累积；07-22 版清空后丢了表头，不跟。
- **P5、L5、S1、S2 的 βλ、L3 的椭圆判据、L1 的越界**是 07-22 版的回归或缺陷；**P6 GenBunch、O4 诊断文件、O6 BeamSet.plt 首字节**没有程序读取或依赖，维持不跟。

## 7. 用 07-22 版逐项核对新功能（2026-11-17）

在 XPS 上用 07-22 版 AVAS.dll（与 IMP-AVAS 仓库当前根目录的 AVAS.dll 相同，SHA-1 93fdc20d8a24；仓库 2026-11-16 的提交只改了分析脚本，没有新内核）和新内核 CI 预编译库（默认模式）跑全部 `M10_*` 算例及 S2a、SP2、SP3、EP_D18，逐项比较。07-22 版需要随附的 fftw 与 MSVCP140 才能加载。

| 项 | 结果 |
|---|---|
| D1 参考能量 | 两边都取 kneticenergy（1.6 MeV 算例同步粒子入口 1.600001 MeV）；出口同步能量相差 1e-5 MeV，outData 平均能量相差 1e-5、rms 相同到 4 位。φs：新内核解出 −33.000°，07-22 版（与 04-02 版、兼容模式相同）扫相位得 −32.93° |
| D2 initpos／initmom | 单粒子轨迹一致（x、y 最大差 1 µm，W 差 2e-5 MeV，来自 φs 的 0.07°）。07-22 版忽略 displacepos（S2a 粒子在轴上），新内核两套都认 |
| D3 SingleParticlePlane.txt | 格式相同，数值相同到 1e-5 相对。07-22 版的 SingleParticle.txt 没有表头、单粒子不写 DataSet 与 outData，新内核保留 |
| D4 命名与密集输出面 | 文件名相同；三个间距 3 mm／0.5 mm 的面与单独放置的面，07-22 版与新内核的粒子坐标相差 1e-8 m、相位 5e-5 rad（同一面单独放置时差别相同）。EP_D18 两边都写出两个面。命名面在末端时 07-22 版只写 `NAME_<L>.dst`，新内核另写 `outData_<L>.dst` |
| D5 边界 | 矩形／椭圆管、薄准直器：损失的粒子（3041、2342 个）与存活数完全相同。差别只在 collisionData.txt：07-22 版把一部分粒子重复记录（5000 行对 3041 个粒子、3599 行对 2342 个），粒子从入口面在孔径外进入时 07-22 版记在进入后的第一步（z = 0.100143），新内核记在入口面上 |
| D5 复合段 | 07-22 版只有块以 `superposeout` 结束、且每个子形状行写出 `RLP` 加 6 个放置值时才能运行，`superposeend` 或省略 RLP 都在“Initialising boundary...”处抛 C++ 异常结束进程。按它能接受的写法，两边损失的粒子同为 2030 个、存活数相同（07-22 版 2574 行中 544 行是重复记录）。新内核两种写法都接受 |
| D6 Ke = 0 | 两边都与漂移段逐字节相同，synData 中是 drift |
| D7 纵向周期盒 | rms x、y、z 全程相对差 ≤ 7e-5（07-22 版周期 βλ 与新内核 γβλ 在 1.5 MeV 只差 1.6e-3） |
| S4 停滞判丢 | 两边都不误判，三个粒子到达两个输出面 |
| SP2 块首射频腔 | 07-22 版 φs 为 NaN、不加速；新内核 −33°、加速 |

结论：D1–D7 的新内核实现与 07-22 版在物理结果上一致，差别都来自已知的约定（φs 求解精度、平均能量定义、周期长度）或 07-22 版自身的输出缺陷（重复的碰撞记录、表头丢失、复合段写法限制与崩溃）。

决定（2026-11-17，与用户商定，重申 D8）：随附的原内核与兼容模式的逐字节基准继续保持 2026-04-02 版，不换成 07-22 版，也不另附 07-22 版作可选原内核。07-22 版的新功能由新内核默认模式提供（上表已核对一致），它的输出缺陷与崩溃不进入随附内核。
