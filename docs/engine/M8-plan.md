# M8 方案：新内核设为默认（淘汰计划第二阶段，2026-11-15，待用户确认）

M7 已随 AVAS 2.0.0 · b576e30 发布：新内核在 Windows／Linux 上是可选的“新内核（预览）”，macOS 上没有原内核，默认用新内核。
M8 要做的是**把默认切到新内核**。

这一步会改变所有没有显式选择内核的项目的计算结果，所以分两段：
- **M8a（准备）**：比对工具、性能测量，由用户在真实项目上验收。
- **M8b（切换）**：验收通过后实施。

本文件先列出诊断与待定点，确定后再一次实施。

不在 M8 里做的事：
- 删除原内核二进制（第三阶段，条件见第 4 节）；
- RFQ（仍等输入样例，理由见待定点 6）。

## 1. 现状诊断

### 1.1 默认值从哪里来

内核选择的优先级是：命令行 > 环境变量 `AVAS_ENGINE*` > 项目 ini.ini `[engine]` > 内置默认值（`avas/engines.py: resolve_choice`）。
- 内置默认值是 `default_kernel()`：有原内核的平台（x86-64 Windows／Linux）取 `original`，其余取 `new`。
- 设备、精度等的默认是 `DEFAULTS`：auto／auto／all／0／none。

所以切换默认只需改 `default_kernel()`。会受影响的是：
- ini.ini 没有 `[engine] kernel` 的项目——目前几乎所有项目，因为模拟设置页只在用户改过时才写这一段；
- 研究层、AI 沙盒和入门教程。它们都经 `avas run` 子进程，跟随同一默认值。

模拟设置页、运行记录（`avas_run.json` 的 `engine`）、结果页、运行对比都已经标明每次运行实际用的内核与设备（M7b）。
研究层缓存按结果档区分（M7a）：切换后不会错用原内核的旧缓存，只会重新计算。

### 1.2 切换后结果会怎样变

新内核默认模式与原内核**不逐位相同**，差别分三类。

**（a）修正原内核的缺陷**（每项都先用 DLL 实验确认，见 M1–M6 notes）。对用户结果影响较大的有：
- **SPICNIC 格林函数**（M4）：原内核对拉长的格子（长束团、直流束）空间电荷明显偏弱，DC KV 束的空间电荷增长只有解析值的 38–81 %，且随网格剧烈变化；新内核收敛到 1 % 以内。普通束团（格子接近立方）几乎不变。
- **V3 = 0 的同步相位**：原内核有约 +0.07° 的系统偏差。
- **V3 = 2 腔影响下游腔的相位扫描**。
- **硬边元件**：硬边元件内的空间电荷能量变化被抵消；磁铁出口能量有约 1e-4 的相对变化。
- **某些元件写法**：L = 0 的 bend 只走半个弧长；multipole 的场强与 G² 成正比；含 RF 腔的 superpose 组不加速。
- **随机数与线程**：固定种子时 x 与相位完全相关（原内核 randomseed 非 0 时的相关系数为 −1）；结果随线程数变化，quad 等元件中的空间电荷多线程有数据竞争。
- **误差研究**：多个样本之间误差累积。

**（b）随机数发生器不同**。同一个 `randomseed` 生成的粒子不同，有限粒子数的结果只在统计意义上一致。

**（c）新功能**：PICNIC、GPU（CUDA／Metal）、`statoutputinterval` 等。只有用户写了才生效，不影响默认结果。

示例：SC1 算例中，默认模式与兼容模式的 DataSet 相差最大 0.7 %（M4）。对真实项目的影响**还没有测过**，这是 M8a 要补的。

**兼容模式**（`compat = dll`）在 Windows 上与原 AVAS.dll 逐字节一致（CI 与 XPS 均已核实），只能在 CPU 上运行。
所以即使将来删掉原内核，旧结果仍能在新内核里复现。

### 1.3 还不知道的事

- **真实项目上的差别**：到目前为止，只比对过 194 个规格算例和示例项目 hwr010。
- **CPU 速度**：只在小算例上量过（macOS 上 SPICNIC 与原内核相当），没有在用户的项目规模上与 AVAS.dll 比较过。
- **AGENTS.md 第 6 节**：有若干条是用原内核核实的约定或现象。例如“内核单粒子运行约三成整列 NaN”“固定种子后可重复”，以及质心、轨道响应矩阵与线性模型的比较。切换后这些描述要分清说的是哪个内核，工具（`tools/compare_*_engine.py`）要能对新内核重跑。
- **RFQ**：原内核运行 RFQ 即崩溃（M2），新内核明确报错“not implemented”。两者都不能算 RFQ，切换不会让 RFQ 变差。

### 1.4 Linux 的旧 GPU 通路

ini.ini 的 `[input] device = gpu` 走 `avas/gpu/` 里预编译的 libPIC.so（只有 Linux，`avas/core/MultiParticle.py`）。
新内核的 CUDA PICNIC 已经覆盖它的功能，并修正了 libPIC.so 的三处缺陷（场比原库强约 3 %，M6b）。切换后两条 GPU 通路并存，容易混淆。

### 1.5 测试

- `tests/` 里不少测试默认跑原内核。
- 切换后，Windows CI 的快速 pytest 会改用新内核。凡是断言原内核特有行为的测试，都要显式指定 `--engine original`；Linux／macOS 的情况同样处理。

## 2. 切换前的准备（M8a）

1. **内核比对工具**：`tools/compare_kernels.py --input <项目> [--particles N]`。
   - 在临时副本上依次运行原内核、新内核兼容模式、新内核默认模式（CPU，以及本机有 GPU 时的 auto）。不碰项目的 InputFile／OutputFile。
   - 输出一张表：沿 z 的 rms 尺寸、发射度、传输率、能量与同步相位的最大差别和末端差别，并给出新旧兼容模式是否逐字节一致。
   - 默认模式与原内核的差别分两部分：一部分与随机种子起伏相当，另一部分超出起伏、来自缺陷修正。工具用两个种子估计起伏，把这两部分区分开。
2. **性能测量**：同一工具记录各次运行的耗时与线程数。
   - 在示例项目和用户提供的项目上，比较原内核 CPU、新内核 CPU、新内核 GPU 的耗时。
   - 结果写进 M6-notes 的性能表。
3. **用户验收**：用户在自己的真实项目（建议至少 2 个，其中有含空间电荷的）上用工具比对，或在模拟设置页里直接切换比较。
   - 差别超出预期时逐项定位。工具会指出差别从哪个元件开始出现。
4. **重跑核实工具**：用新内核重跑质心、轨道响应矩阵等工具（`tools/compare_*_engine.py` 加 `--engine`），更新 AGENTS.md 第 6 节的表述。

## 3. 切换（M8b，验收通过后）

1. **内置默认**：`default_kernel()` 在所有平台返回 `new`。设备、精度维持 auto，模式维持默认（修正）模式；见待定点 2、3。
2. **已有项目**：见待定点 4。推荐不自动改写任何项目文件。
3. **全局默认内核**：见待定点 5。推荐在菜单“设置”中加一个“默认计算内核”偏好，存于 gui.json。
   - 优先级：命令行 > 环境变量 > 项目 ini > 全局偏好 > 内置默认。
   - 不想马上切换的用户可以一次改回原内核，而不必逐个项目设置。
4. **一次性提示**：更新后第一次启动时说明：
   - 默认内核已切换；
   - 结果为什么会和以前不同（列出影响较大的修正）；
   - 怎样改回原内核，或改用兼容模式复现旧结果。
5. **对比提示**：运行页“与前一次运行对比”和结果页“运行对比”在两次运行所用内核或模式不同时提示：“差别可能来自内核”。
6. **界面与文档**：
   - 模拟设置页的标签从“新内核（预览）”改为“新内核”，原内核标“原内核（将淘汰）”；
   - README（中英文）、使用说明、AI 提示词（`ai/avas_prompt.py`）、入门中提到内核的地方同步修改；
   - AGENTS.md 第 1 节写明默认内核。
7. **测试**：
   - 断言原内核行为的测试改为显式选原内核；
   - 新增“默认内核为 new”的测试；
   - CI 的冒烟测试同时跑两个内核。
8. **Linux 旧 GPU 通路**：`[input] device = gpu` 运行时给出弃用提示，建议改用新内核的 NVIDIA 显卡（见待定点 8）。

## 4. 原内核的保留与第三阶段

- M8 之后原内核仍随包发布，可在模拟设置页和命令行选择。
- 第三阶段删除 `avas/engine/` 下的原内核二进制和 `avas/gpu/`。建议条件：
  - 切换后至少经过 3 个月、2 次发布；
  - 期间没有只能用原内核解决的问题。
- 删除后，兼容模式仍能在 CPU 上逐字节复现原内核的结果。

## 6. 实施顺序

1. 用户确认待定点。
2. M8a：比对工具与性能测量（我来做，在 Mac 和 XPS 上验证），用户在真实项目上验收，根据结果决定是否进入 M8b。
3. M8b：一次提交完成第 3 节全部内容，CI 全绿、XPS 打包冒烟测试后经用户同意合并到 main，随下一次发布生效。
