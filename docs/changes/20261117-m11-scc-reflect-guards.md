# 新内核：硬边元件前的空间电荷补偿生效、反射粒子不再使运行卡住；原内核运行前的提示

• 新内核默认模式：写在四极铁、螺线管、二极铁或边缘场元件前面的 `spacechargecomp` 现在从该元件起生效（原来要等到下一个场图或漂移段才起作用）；写在第一个元件之前时从起点就生效（原来报 “Tcode won't start”）。“复现 AVAS.dll”模式与原内核相同：写在四极铁等元件前不起作用；读入粒子文件、写在第一个元件之前时也不再报错，而是像原内核一样在束团越过起点后生效。
• 新内核默认模式：superposeout 叠加块里被静电场反射、退回块入口之前的粒子判为丢失，运行正常结束（原来两个内核都会一直运行下去不结束）；“复现 AVAS.dll”模式在这种情况下给出明确报错。
• 选用原内核或“复现 AVAS.dll”模式且启用了边界时，若 boundary.txt 含 superpose 块，运行前直接提示改用新内核默认模式（原内核读到这种块会异常退出）；lattice 中射频腔位于叠加块开头时（原内核里这个腔没有场、束流不加速），运行前给出提醒。
• 在 Linux 上用原内核运行时，自动把运行副本里的 boundary.txt 换成 LF 换行（原内核遇到 Windows 换行的 boundary.txt 会崩溃）；项目里的原文件不改动。
• 内部：补充了停滞判丢、RFQ 扫相位、进度行、SimulationTime.txt、随机种子 0 可复现等检验，新算例的原内核参考结果待在 Windows 上生成。
